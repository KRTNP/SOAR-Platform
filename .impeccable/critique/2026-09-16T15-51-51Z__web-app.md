# Design Specificity Verdict

**Category-interchangeable.** Swap the nouns and this is any dark SOC dashboard from the last decade.

The visual world is a default, not a decision: `design-tokens.css:8-29` is the standard calm-dark-command-center kit. `--radius-sm: 4px` / `--radius-md: 5px` are 1px apart — not a system. Typography is where the absence of authorship is measurable: 8 font sizes across a 3.5px band (10, 10.5, 11, 11.5, 12, 12.5, 13, 13.5), 168 usages, on top of Tailwind's own scale. Structural sameness is severe: `page.tsx:29-58` and `approvals/page.tsx:47-74` are the same header; audit/settings/metrics each render the same bordered-table-in-a-rounded-box. Five pages, one template.

The authored moments are in the reasoning, not the form: badge suppression (`badges.tsx:82-97`) and the metrics page naming the KPIs it refuses to fake (`metrics/page.tsx:111-114`).

The product's stated differentiator — "always show why an action was permitted and what would undo it" — has no visual expression anywhere. `PendingAction.mode`, `idempotency_key`, `expires_at` are typed (`types.ts:56-60`) and rendered nowhere (verified by grep across `app/` and `components/`).

**Deterministic scan:** 1 finding, exit 2. `side-tab` at `cases/[caseId]/page.tsx:122` (`border-l-2 border-accent` on the Working Hypothesis blockquote) — real but weak signal: 2px, on a pull-quote, single occurrence in the tree. More informative is what it did not find: zero raw hex/rgb across 36 files, no per-component focus hacks (one global rule at `globals.css:45`), reduced-motion covered. The code is mechanically clean; the problems are structural and product-level, which no detector catches.

**Visual overlays:** none. No injection, no browser overlay (no browser automation, backend not running, `AGENTS.md` bars starting services without authorization).

# Emotional Journey

Arrival is the first valley: the console answers "here are your cases by severity" to a user whose question is "what is waiting on me?" The peak is wrong — approving a real firewall block is the smallest UI in the app (a 28px cyan button in a table cell, `approval-actions.tsx:139`), while deleting a tenant gets a modal and "This cannot be undone" (`delete-button.tsx:37`). Reassurance at the high-stakes moment is absent; what exists is false reassurance (`Sidebar.tsx:104`). The end is a disappearance — `revalidatePath` removes the row with no "Blocked X · auto-releases in 24h · Release now", so the user alt-tabs to OPNsense to verify. The UI is training that distrust.

# What's Working

1. **Badge suppression as an editorial act** (`badges.tsx:82-97`) — colored pill reserved for `denied`/`tampered`, quiet check for the majority outcome. A 200-row audit log has exactly as many loud pixels as there are problems.
2. **Admitting what the system cannot know** — `metrics/page.tsx:111-114` names three KPIs it refuses to fake and cites the ADR; `search/page.tsx:34-37` labels results as a derived projection.
3. **`ProblemBanner` carrying `code` + `request_id`**, and `approveActionAction` returning `{ error }` rather than throwing so the real Problem title survives Next.js stripping (`actions.ts:44-52`).

# Priority Issues

**[P0] The approve decision shows no consequence before commitment.** `approvals/page.tsx:216` and `status-control.tsx:453` fire approve+execute (`actions.ts:59-60`) on one click. `mode`, `expires_at`, `idempotency_key` are typed and rendered nowhere. Violates PRODUCT.md principle 4 and erases the product's differentiator. Fix: a confirmation step (reuse `Modal.tsx`) stating intent, target+type, `dry_run`/`execute` as the loudest element, risk, requesting actor, policy version, TTL, rollback path; render `mode` as a persistent pill on every `PendingAction` surface. → `/impeccable harden`

**[P0] The sidebar asserts "Dry-run mode" when it does not know.** `Sidebar.tsx:104` `connectorVersion?.includes("mock") ?? true` — an unreachable backend (swallowed at `layout.tsx:27`) renders a confident safety claim. Fix: three states — live / dry-run / unknown, with unknown in warn treatment gating execute-class actions. → `/impeccable harden`

**[P1] Arrival does not answer "what needs me?".** `/` is the case queue; nothing carries a pending-approval count. Contradicts principle 1 and the episodic session shape. Fix: count on the Approvals nav item plus a "Waiting on you" block pinned above the severity groups. Commit `8e8d852` over-corrected — the one badge that earns its place went with the rest. → `/impeccable layout`

**[P1] Mocked connectors are visually indistinguishable from real ones.** `VerdictBadge` (`badges.tsx:52`) renders mock-TI verdicts identically to real data; the "this is mock" note lives only in a code comment. On a screen used to decide whether to block an address, this is a correctness hazard. Fix: a consistent `mocked` marker on every mock-sourced value, plus a legend. → `/impeccable clarify`

**[P2] No type/spacing system, and dominant secondary text fails WCAG AA.** 8 font sizes in a 3.5px band plus arbitrary spacing (`gap-[18px]/[22px]/[28px]`, `px-[34px]`); `--color-text-tertiary` on `--color-surface` computes to ~2.9:1, below the 4.5:1 floor, and it carries every page description, all table metadata, the audit Reason column and Timeline timestamps. Fix: a 5-step type scale and 4/8px spacing scale as tokens; delete arbitrary values; raise tertiary to pass AA. → `/impeccable typeset` then `/impeccable colorize`

# Questions to Consider

1. If the product's whole claim is "we can always show what would undo this," why is `mode` in the type file and on no screen? What would the approve dialog look like designed as *the* product surface rather than a table cell?
2. What if `/` were a "Waiting on you" screen — approvals first, then what changed since the last visit — and the case queue were one nav item among equals?
3. The user alt-tabs to OPNsense to verify what the console said. What would have to appear after an approve for that tab switch to stop?
4. Badges were removed everywhere in `8e8d852`. Which single number in this app is worth a badge, and is it displayed anywhere at all?
5. What if mocked data were ugly on purpose — dashed, desaturated, visibly provisional — so real intel earned its color?
6. Eight font sizes between 10px and 13.5px. If you were allowed four, which four, and which screen breaks?
7. The system defaults to `dry_run` because a playbook cannot merge otherwise (adr/0003). Should the interface likewise be unable to render an execute-mode approve button without displaying the rollback path?
