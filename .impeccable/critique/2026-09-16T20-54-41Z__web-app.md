# Design Specificity Verdict

**Authored for this product — but the authorship lives in the epistemics, not the composition.** The state logic is unmistakably this product's: `connectorState()` refuses to collapse "unknown" into "dry_run"; the post-execute receipt renders the connector's prose verbatim and declines to compile it into a "Verified" badge; `isReversible` names the TTL mechanism and refuses to invent a release timestamp; `approveActionAction` reports which of two non-atomic calls failed; metrics names the KPIs it cannot compute. No generic dashboard makes those choices.

The shell is category-standard: 236px dark rail, six nav items, stat tiles, bordered card sections. The case page imports a report-template register ("Executive Summary", "Artifact Evidence") that belongs to a deliverable for someone else, not to a solo operator asking what just happened.

**Deterministic scan:** 0 findings, exit 0 (re-run with `--no-config` to rule out suppression). No arbitrary font sizes, no arbitrary rhythm spacing, no raw color literals anywhere in `web/app` or `web/components`. Contrast independently recomputed oklch → linear sRGB → WCAG: text-secondary 7.94–10.54:1, text-tertiary 4.77–6.33:1 across all four surfaces — AA clear. Two real defects found outside the detector: an unprefixed `py-5` beside `py-2.5` in `Sidebar.tsx` (breakpoint lost during a class split), and `--severity-informational` at 62% falling to 4.46:1 / 4.07:1 on raised/hover surfaces — a latent hazard with no current call site. Both fixed.

**Visual overlays:** none. No browser automation exposed; backend not running; `AGENTS.md` bars starting services without authorization.

# Emotional Journey

**Peak — arrival.** Header counts, "new since last visit", then the amber panel with Review/Reject inline; principle 1 answered without a click.

**Peak — the moment after.** The "Executed" receipt states the API-reported status, says plainly it is not an independent re-check, offers on-demand `TargetCheck`, and puts "Release now" beside the act. The category has not solved post-action verification; this is the strongest work in the codebase.

**Valley — reject.** Type a reason into a table-cell input, press Confirm, row silently disappears. Half the gated-action job ends in a shrug.

**Valley — the dialog's blind spot.** At the highest-stakes moment the screen shows target, mode, risk, requester, expiry, rollback — and not the justification or the case. Consequence visible; cause not.

**Valley — mobile.** Below `md` the whole connector/dry-run block is dropped while the approve path still offers to execute.

# What's Working

1. **Refusing to guess is implemented, not asserted.** Three-state connector; `unresolved` count on the queue; `return {}` when the post-execute confirmation read fails rather than inventing a status. Each is a place where the easy code path is a comforting lie.
2. **One decision, one interface.** `ApprovalRowActions` is the same component on the queue, the approvals table, the mobile card and the case sidebar, differing only by a `size` token. The approve gate cannot drift between entry points.
3. **The badge loudness gradient.** `verified`, `approved`, `allowed`, `dry run` are deliberately quiet so `tampered`, `denied` and `execute` carry the only pills on screen. Signal design, not decoration.

# Priority Issues

**[P1] Triage has no surface for events.** `GET /v1/events` is implemented and the console never calls it. An ingested event that did not correlate into a case is invisible, so one of four equally weighted jobs sends the operator back to Wazuh. → `/impeccable shape`

**[P1] The approve dialog omits why the action was requested.** `PendingAction.reason` is typed and rendered on the case page but absent from `ApproveDialog`. The operator authorizes a live firewall write without the stated cause or the case ID on screen. → `/impeccable clarify`

**[P2] Ceremony is inverted for destructive settings changes.** Closing a case requires a typed reason; deleting a tenant — which invalidates an API key — is one button. The lighter gate guards the heavier consequence. → `/impeccable harden`

**[P2] Lists silently truncate at 100 and present the truncation as a total.** `next_cursor` is typed but never used; audit is hard-capped at 100 with no cursor, so record 101 is unreachable from a console whose value proposition is the record. → `/impeccable harden`

**[P2] Rejection ends in silence, and export loses its Problem.** `submitReject` has no success path; `exportCaseAction` is the only server action that throws instead of returning `{error}`. → `/impeccable polish`

# Persona Red Flags

**Alex (power user):** no keyboard shortcut to approve or reject; audit filters are `useState` not URL params so refresh loses the view while `/search` uses a form GET; no bulk action anywhere.

**Sam (screen reader / keyboard):** `<th>` elements in the audit and settings tables omit `scope="col"` while approvals sets it; full timestamps live only in `title` attributes; `/settings` and `/search` have no `loading.tsx` so a slow API gives no `aria-busy` state.

**Riley (stress tester):** `pendingDecisions` issues one `getAction` per pending approval with no concurrency cap, each on an 8s budget; `NewSinceLastVisit` writes the watermark on mount so a hard refresh mid-session makes everything "not new"; over 100 cases the queue counts become quietly wrong.

**The solo lab operator:** if correlation did not fire there is nowhere to see the events that did arrive; "3 cases new or updated" gives a count but marks no rows; on a phone the live/dry-run state is lost entirely.

# Minor Observations

- `ApproveDialog` hides "Predicted effect" for unsupported intents while "Rollback" says "Not documented for this intent" — two honesty conventions three rows apart.
- `cases/[caseId]/page.tsx` uses 4-space indentation; every other file uses 2.
- Page headers diverge: queue and approvals get `border-b border-border pb-4`; metrics, audit, search, settings do not.
- `role="alert"` paired with `aria-live="polite"` is contradictory — `alert` already implies assertive.
- Truncating a ULID case ID to 19 chars leaves the non-distinguishing prefix; the entropy is at the end.

# Questions to Consider

1. If the operator's arrival question is "what just happened," why is the queue's primary axis severity rather than time?
2. The receipt refuses to compile the connector's prose into a verdict, correctly. Would Kubernetes' third condition value — `Unknown` — let you render a structured state without inventing one?
3. Approve gets a review sheet, a receipt, a target check and an undo. Reject gets a text input in a table cell. Is a rejection genuinely the low-consequence direction, or just the one nobody designed?
4. Every gated action's `reason` is recorded and shown on the case page — but not at the one moment a human is deciding on it. What else is the system already telling the truth about that the decision screen isn't showing?
