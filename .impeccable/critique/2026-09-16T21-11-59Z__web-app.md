# What's Working

1. **Refusing to compile prose into a verdict**, and refusing to compute a release time from an unexposed field — principle 3 enforced in code, not comments.
2. **Three-state connector.** Unreachable metrics can no longer render a reassuring "dry-run", and the mobile bar keeps the marker for exactly the two states that change what a tap means.
3. **Partial-failure honesty.** `approveActionAction` reports which of two non-atomic calls failed and the UI renders a distinct "Approved, but not executed" state with a scoped retry. Most SOAR consoles show one generic failure here.

# Priority Issues (as raised; first four addressed this round)

**[P1] "Target state" framed a canned planning message as an observation.** With the mock connector the endpoint always returns a generic dry-run sentence and the UI could not distinguish it, yet labelled it "what it currently sees" with a timestamp. Post-action verification is the one thing the category has not solved; claiming it falsely is worse than omitting it. **Fixed:** `previewActionAction` now reports `liveConnector`, and the panel states plainly when the answer is a plan rather than an observation.

**[P2] Decided history discarded contract data the product exists to show.** `approved_by`, `reason` and `decided_at` were typed and rendered nowhere; the rejection reason the operator was forced to type appeared on no screen. **Fixed:** historical rows now trade Risk/Expires for Decided (who + when) and Reason, on both table and mobile card.

**[P2] Release had no receipt and no revalidation.** Released from `/approvals` or `/`, neither refreshed. **Fixed:** revalidate set widened to `/approvals` and `/`.

**[P2] The case timeline cannot show the containment decision.** Approve, execute and release write no timeline entry server-side. **Fixed (UI half):** a note under the timeline names the gap and points at the audit log, matching the metrics convention. The server-side half remains open.

**[P3] No accelerators at all.** Heuristic 7 scored 1. For a solo operator whose session is "decide on 1–8 things", `j`/`k` row movement, `a`/`r` on a focused row, and URL-backed audit filters would cut the session in half. → `/impeccable adapt`

# Minor Observations

- Three time formats across three surfaces; `RelativeTime` with a `title` should be the single convention.
- `Modal`'s `id="modal-title"` is hardcoded; `useId()` would survive two co-mounted modals.
- `transition-*` and `active:scale-[0.98]` escape the reduced-motion block.
- "Pending Approvals" / "Decided History" are Title Case while every other section heading is sentence case or uppercase-tracked.
- `search/page.tsx` explains its 503 in a code comment; the user gets an unexplained Problem banner.
- 11px is doing too much work; decision-relevant copy should be `text-xs`.

# Questions to Consider

- If the contract cannot verify a block, should the receipt offer verification at all — or hand over the `pfctl` command and stop pretending?
- The API loads the action beside the approval and throws it away. Should the UI keep paying an N+1 for a field the server already had?
- One click performs approve *and* execute. Does "consequence before commitment" survive collapsing two contract steps into one button?
- Kubernetes separates `spec` from `status` with a third value, `Unknown`. This console already models that for the connector. Why not for every action's target state?
